- **Backend fait foi, 100 % de parité conservée** : 1:1 (texte/vocal/fichier 50 Mo, note du jour, réponse-citation, réactions, favoris de messages, édition 15 min, suppression pour moi / pour tous 48 h, épinglage conversations max 3, sourdine 8h/1sem/toujours, non-lus, archivage, recherche dans le fil, mentions @, présence, accusés lecture) + groupes complets (création nom/photo/couleur, admins min 1, lectures par membre, renommage, archivage/désarchivage, suppression confirmée). - **Tribunal** : audit intégration 6.5 + audit UI 6 → correcteur 25/25 fixes. Points structurants :
  - Sécurité : `createGroup`/`addMembers` valident le périmètre équipe via `canCommunicate` (exporté de messages.ts) ; `assertMessageParticipant` sur réactions/favoris/suppressions ; typing vérifie l'appartenance au groupe ; **sourdine réelle** (send saute la notif si muté ; sendGroupMessage notifie les membres non mutés) ; 50 Mo vérifié serveur (taille déclarée + réelle via `ctx.db.system.get`).

  - UX scellée : auto-scroll intelligent (`isAtBottom` seuil 80px, bouton « Nouveaux messages ↓ », jamais arraché pendant la lecture), envoi optimiste (`.mx-pending`, restauration + dialog en cas d'échec), composer auto-resize 120px, actions de message au tap sous `@media (hover:none)`, mentions pilotables au clavier, Escape en pile, **aucune scrollbar visible** (ne jamais styler `::-webkit-scrollbar` dans un module : le masquage global fait foi), `GROUP_COLORS` monochromes pierre/champagne, « favoris » de messages ≠ « épingler » une conversation ≠ « note épinglée » (3 mots distincts), rôle `minimaker` = « Miniamaker ».

**2e passe fidélité pixel (2026-07-08, commit 76eb583, Jonathan « pas pixel-perfect, responsive mauvais, photo pas la mienne »)** — tribunal 5 juges (pixel 8, structure 9, couleurs 9, avatars 6, RESPONSIVE 3) + correcteur. Leçons scellées :
- **AVATAR = `resolveAvatarUrl(me, clerkUser?.imageUrl)` de `src/lib/avatar.ts`, PARTOUT** (miroir de AppSidebar). Le bug « c'est pas ma photo » venait d'un `useUser().imageUrl` Clerk brut sur MON avatar (bulles + composer) : il faut `useQuery(api.users.getMe)` + resolveAvatarUrl. Les membres de groupe résolvent `profileImageId → storage.getUrl → imageUrl` (comme messages.ts:381-385) dans getGroup ET listMyGroups.
- **RESPONSIVE — piège shell CRITIQUE** : en mobile (`max-width:767px`) `shell.css` force `.brvndlab-shell > main { height:auto !important; overflow:visible !important }` (pour le pull-to-refresh). Donc un module full-height NE PEUT PAS utiliser `height:calc(100%...)` en mobile (100% d'un parent height:auto = effondré). Solution scellée : `height:calc(100dvh - var(--mx-head,72px) - var(--mx-nav,56px))`. Header mobile ≈ 72px (pas 62px), bottom-nav `.bvh-bn` ≈ 56px (z-100). Mesurer via ResizeObserver sur `.bvh-head`/`.bvh-bn` + remesure `document.fonts.ready`. **Mode une-colonne (data-pane) doit couvrir jusqu'à 1023px** (tablette incluse), desktop 2-colonnes seulement `>=1024px`. Composer : `padding-bottom:calc(12px + var(--mx-nav,56px) + env(safe-area-inset-bottom))`. Cibles tactiles 44px en mobile.
- Structure : « Nouveau message » = bouton texte labellisé (pas icône muette). Segment filtres = 3 tabs EXACTEMENT (Tous/Non lus/Groupes) ; Archivés hors segment (ligne discrète). GROUP_COLORS monochromes pierre (jamais #C6A86E champagne). Danger tokenisé `--mx-danger:#BC4B3B`.
