Depuis la page d'un angle (`/angles/[id]`), le bouton **Script vidéo** (le seul actif du bloc « Transformer cet angle en » ; Story/Carousel/Lead magnet restent « Bientôt ») mène à un mini-quiz à boutons puis génère le script.

**Flow** : `/angles/[id]/script` (nouvelle page quiz) → 3 questions : Format (Short/Long), Objectif (TOFU/MOFU/BOFU, pré-rempli depuis `angle.funnel`), puis la 3e dépend du format. SHORT → Structure (Classique = problème→solution / Histoire / Liste). LONG (scellé 2026-06-19) → « Type de vidéo », **4 types finaux, un par INTENTION, labels business** : Vidéo éducative (tu enseignes), Étude de cas (tu décortiques un cas réel, le tien ou un client → value interne `recit`), Prise de position (tu défends, value interne `these`), VSL (tu vends). Histoire fusionnée dans Étude de cas (même geste : raconter). Jonathan a refusé « récit/cas réel » (pas business) et « thèse » (scolaire). PAS de champ « Autre » libre (Jonathan : « la liberté se trouve dans la discipline » — un champ libre depuis un brainstorm = pas de cadre = pas de sens). « Parole libre » écartée (un script vient d'un brainstorm structuré, pas d'une parole spontanée). En long, SECTIONS ÉMERGENTES : Hook 1er + CTA dernier fixes, le milieu est nommé par sa fonction réelle selon le type (étude de cas → Contexte/Ce qu'on a fait/Résultat ; thèse → Affirmation/Preuves/Objection levée), JAMAIS "problème/solution" imposé. Bouton « Générer » pose `script_context` dans sessionStorage et `router.push("/content/script")`. La page `/content/script` existante fait toute la suite (génération, édition section par section, sauvegarde pipeline) — non touchée.

**Générateur IA câblé** : `/api/generate-script` n'est PLUS un stub 501. Il appelle `callAi({feature:"script_premium"})` via aiGateway (coût plafonné par DAILY_USER_LIMIT comme le brainstorm), injecte le Brand OS côté serveur (`api.brandDna.getBrandDna`), et renvoie `{title, platform, funnel, estimatedDuration, wordCount, sections[]}`. Prompt = scénariste FR, script PARLÉ 1re personne, règles short vs long + intent funnel + structure.

**RÈGLES DE COMMUNICATION CHIRURGICALE bakées dans le prompt (toujours actives, MÊME si Brand OS coupé)** — extraites de la skill `youtube-script` (~/.claude/commands/youtube-script.md) : français ORAL (supprimer le "ne" de négation), tirets longs (—) INTERDITS (apartés en parenthèses), ZÉRO anaphore/série/triptyque ("ce n'est pas X, Y, Z" interdit), pas de listes en virgules (relier avec "et"), zéro répétition de mot en phrases consécutives, zéro parabole/dramatisation, transitions directes non narratives, marqueurs vivants OK sauf "et en fait", exemples avant théorie, possessifs au spectateur (ton/tes), zéro chiffre inventé. RÈGLES UNIVERSELLES ABSOLUES (ajoutées 2026-06-19, tolérance zéro car produit vendu — fautes de français qu'aucun utilisateur ne doit voir, quel que soit son Brand OS) : (a) structure "Pas parce que X. Parce que Y." INTERDITE (formulaic/IA, ex banni : "Pas parce que c'est violent. La voix/vocabulaire/niche spécifiques de Jonathan (upseller, funnel, ICP coachs, bio conclusion) restent au Brand OS, PAS bakés. C'est un premier prompt à peaufiner.

**Architecture qualité 3 filets (2026-06-19, exigence "tolérance zéro" car produit vendu)** : (1) prompt de génération avec règles ; (2) PASSAGE ÉDITEUR = 2e appel callAi dédié uniquement à corriger fautes + fluidité (relier le haché, ponts naturels, pas de phrase en suspens) ; (3) CONTRÔLE déterministe en code : `findViolations()` scanne le script final par regex (tiret long, "Pas parce que…", triptyque "pas X, pas Y, pas Z") et relance l'éditeur en correction ciblée jusqu'à 2 reprises ; le tiret long est supprimé à 100 % par `stripDashes`. Garantie honnête donnée à Jonathan : 100 % sur les motifs détectables en code (tirets, "Pas parce que", triptyques) ; mots-marteau/"ne"/haché fortement réduits par l'éditeur mais PAS garantis (les détecter sans casser du bon texte est risqué). Ne jamais promettre 100 % sur tout (fausse certitude). Coût : jusqu'à ~4 appels Sonnet par script (génération + 1 à 3 éditeurs), plafonné par DAILY_USER_LIMIT. Détecteurs `findViolations` (2026-06-19) : tiret long, phrase démarrant par "Parce que" (forme hachée — affiné pour ne PAS flaguer "non pas parce que X, mais parce que Y" qui est correct), triptyque généralisé (3 segments courts virgulés sans "et"/"ou", pas que les "pas X"), mélange tu/vous (tout doit être "tu"). Règle factuelle (prompt seul, pas code) : entités réelles = identité exacte la plus connue (Tadao Ando = architecte PAS entrepreneur), corriger les descriptions floues de la source, enrichir avec un fait connu CERTAIN même hors brainstorm (ex Dana White = patron UFC), jamais un fait incertain.

Parce que Y." (7/9) ; anaphores, mots-marteau, paraboles filées (muscle/ring/charrue). Factuel = propre (Ando=architecte partout, fix tenu). Leçon clé : **le prompt seul est violé 9/9, il FAUT un contrôle qui relance en boucle**.

**Correctifs appliqués (architecture finale du générateur)** : prompt durci (max 2 éléments coordonnés jamais 3 même avec "et" ; pas de métaphore filée, sport = fait biographique pas image ; pas de haché ; 6-8 sections × ≥320 mots, cible 2000-2400). **Correctif anti-anaphore staccato (2026-06-19, après test live frustré de Jonathan « les pas, pas, pas »)** : le pivot « humain pas IA » avait retiré TOUS les détecteurs de forme en pariant sur le juge ; résultat le hook ressortait « Pas son idée. **Standard d'écriture des stories (2026-06-20, référence Voics/Aura founder story partagée par Jonathan)** : reproche = « tu mets beaucoup trop de texte ». Le vrai standard story = MATURITÉ + STORYTELLING + RYTHME, jamais de bombardement. Règles posées dans le prompt : (1) ULTRA-COURT, **une seule idée par slide, 5-12 mots**, jamais plus de 2 phrases très courtes, lisible en <2s, whitespace = ami ; si beaucoup à dire → PLUS de slides, jamais charger une slide (un mur de texte = échec). (2) **STORYTELLING qui s'enchaîne** : chaque slide avance l'histoire d'UN beat (accroche→montée→tournant→révélation→chute), pas un cours ni un info-dump par slide ; le plaisir vient du rythme slide après slide, pas de la densité. (3) **Rythme** : lignes courtes qui claquent avec sauts de ligne `\n` (« On a fait 50 clients.\nPuis 100. » / amorce en haut + chute en dessous « Aujourd'hui…\nVoics fait 500 000€/mois »). (4) hook 1re slide en 3-5 mots (« Nouveau ici ? »). (5) **gras RARE** : un mot/chiffre max par slide, souvent aucun. (6) Auto privilégie BEAUCOUP de slides courtes (6-12) vs peu de slides denses. Rendu : `whitespace-pre-line` sur le `<p>` pour afficher les `\n`. Exemples de la réf à imiter : « So I built the solution. », « But at 23…\nI had three failed businesses », « I failed at events.\nI failed in ecommerce.\nI failed in software. ».
