Le formulaire de brief thumbnail dans Brvndlab est calqué sur le Tally de référence du Miniamaker avec qui Jonathan travaille (agence établie, DA déjà connue).

**Why:** Le Miniamaker a **déjà la DA du client** (il la maîtrise dès les premiers livrables). Il est inutile de redemander l'ambiance (Old money / Punchy / etc.), les couleurs dominantes, le style visuel à chaque brief. Ces champs alourdissent le form sans apporter de valeur. Le Miniamaker sait déjà.

**Ce qui reste du Tally** :
1. Titre de la vidéo YouTube (required)
2. Brève description de la vidéo (required)
3. Exemples de miniatures que tu aimes (chaînes YT références) (required)
4. Photo(s) à utiliser sur la miniature (upload, required)
5. As-tu une idée de ce que tu veux ? Oui/Non (required)
6. Tes consignes pour la miniature (textarea, conditionnel si Oui)
7. Texte sur la miniature (required)
8. Autres instructions (required ou optionnel)

**Ajouts pertinents validés** :
- **Lien vers la vidéo ou upload** (optionnel) : YouTube unlisted / Google Drive / Dropbox / upload direct. Pour permettre au Miniamaker de visionner la vidéo. Workflow flexible : certains uploadent avant, Jonathan envoie après tournage.
- **Deadline** (required) : pour le pilotage des priorités.

**Ce qu'on NE demande PAS** :
- Ambiance / style (Old money, Punchy, etc.)
- Couleurs dominantes
- A/B test YouTube
- Nombre de variantes

Si un jour Jonathan change de Miniamaker ou veut personnaliser la DA par brief, ces champs pourront être réactivés en option dans les paramètres du formulaire. Mais en standard, non.

**Layout** : **single page**, pas de multi-step. Le Tally est single page, le formulaire Brvndlab aussi. Les étapes décomposées alourdissent inutilement un form déjà court.
