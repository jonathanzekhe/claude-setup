Section accueil des supports R2 client (dossier `VividFlow/bouquet-supreme-r2/`) : structure figée en **2 cartes miroir**, plus jamais 3 temps (Avant/Maintenant/Demain supprimé le 04/06).

- **Carte 1 — AVANT** : label "Avant", titre "Ce qu'on a entendu" = la friction actuelle.
- **Carte 2 — APRÈS** : label "Après", titre "Ce qu'on installe" = ce qui devient plus clair, plus suivi, plus pilotable. Garde le voile cliquable (reveal) pour révéler en live.
- Titre de page type : "Ce qu'on a entendu. Ce qu'on installe." Sous-titre : "Deux lectures simples : la situation actuelle, puis ce qu'on vient rendre plus clair, plus fluide et plus pilotable."

**Ton à respecter (tous les dossiers R2)** : style simple, humain, lisible à l'oral par Jonathan en présentation. Chaque phrase comprise en 3 secondes par un dirigeant. On parle comme à un patron, pas à un expert SaaS/IA. Mots simples, concret métier, ton boomer/patron, phrases courtes. Interdits : jargon IA, jargon SaaS, storytelling long, promesse excessive, dashboard language, mots-clés empilés.

**Why:** Le client (ex: Raphaël, Bula Assurances) est un dirigeant assurance, pas un tech. Le deck se lit à voix haute pendant le R2.

**How to apply:** Cas réel Bula validé d'abord (`bula-assurances-r2/`, alias officiel bula-assurances.vercel.app), PUIS reporter le même pattern dans le template canonique `template/` (template-theta-plum.vercel.app) une fois Jonathan OK.
