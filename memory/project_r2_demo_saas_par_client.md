**ANNÉE COMPLÈTE DE DONNÉES — RÈGLE (17/08/2026, Jonathan)** : une démo R2 doit porter **12 mois d'historique + 6 mois à venir**, sinon aucune période du sélecteur n'a de sens (« les dates ne seront jamais bonnes sans data sur le long terme »). Exigences : AUCUN mois vide sur 13 mois (planchers par mois, mois de bord de fenêtre inclus : il paraît plat sinon) ; **saisonnalité du métier** (atelier textile CH : creux janvier/février et juillet, pics mai/juin, septembre/octobre, décembre) ; **alternance** semaine forte / semaine creuse, jamais une courbe lisse ; densité d'environ 1,5 encaissement par jour ouvré sur les 14 derniers jours (sinon « 7 derniers jours » montre une seule barre) ; montants croissants vers les jours/semaines récents (l'atelier monte) ; « à collecter » = uniquement les échéances à 45 jours (les commandes planifiées plus loin sortent de `payment.amounts`, sinon le KPI explose à 55'790 face aux 810 affichés). Mutations de référence dans `convex/seedInkcloth.ts` : `seedInkclothAnnee`, `seedInkclothAnnee12`, `seedInkclothCombleMois`, `seedInkclothCombleBord`, `fixInkclothAnnee3..6`. **Piège Convex : un nom de champ de retour avec accent (`moisComblés`) fait échouer la mutation** (ASCII only). Le graphe doit être piloté par la période choisie (`from`/`to` passés au composant, granularité jour ≤ 14 j, semaine ≤ 120 j, mois au-delà) et servi par une requête paiements NON fenêtrée, sinon changer de période vide les barres.
